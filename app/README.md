# reels-app — параллельный конвейер на Rust

`reels-app` — обёртка над Python-пакетом `reels` (`python -m reels`), которая гонит **много проектов сразу**
как настоящий конвейер: пока один ролик рендерится на процессоре, следующий уже озвучивается на видеокарте.
Сами этапы (озвучка, выравнивание, музыка, сборка, рендер) по-прежнему делает Python — приложение только
планирует запуски, показывает прогресс и помогает с подтверждениями.

Рабочее пространство `app/`:

| Крейт | Что |
|---|---|
| `reels-core` | типы ответа `status --json`, мост к `python -m reels` (запуск, построчный вывод, коды выхода), поиск проектов, планировщик |
| `reels-app` | команды `run`, `status`, `watch`, `tui` |

## Установка

```bash
cargo install --path app/reels-app      # или: cd app && cargo build --release → app/target/release/reels-app
```

Нужен Python с пакетом `reels` и его зависимостями (см. корневой README). Интерпретатор: `--python`,
иначе `$REELS_PYTHON`, иначе `python3`, иначе `python`. Если пакет не установлен через `pip install -e .`,
приложение само найдёт папку `reels/` в предках текущей папки или рядом с бинарником (сборка из репозитория)
и добавит корень репозитория в `PYTHONPATH`; путь можно задать явно: `--repo /путь/к/local-ai-reels`.

## Команды

```bash
# прогнать все проекты под папками (рекурсивно ищутся reel.yaml; build/, out/, node_modules/, .git/ пропускаются)
reels-app run examples/ ~/reels/inbox
reels-app run examples/ --yes --gpu-slots 1 --cpu-slots 2 --retries 1 --edit linear

# состояние: этапы ✓ готово, ~ устарело, · не выполнялось; точки ✓ подтверждена, … ждёт, – не нужна
reels-app status examples/
reels-app status examples/ --json          # массив как у python -m reels status --json

# демон над папкой-входящими
reels-app watch ~/reels/inbox --interval 5s --grace 2m

# панель в терминале
reels-app tui examples/
```

Пример вывода `run` (без терминала — построчно, в терминале — строка на проект со спиннером):

```
■ проектов: 2; слоты: видеокарта 1, процессор 2
  озвучка и музыка уже готовы у 1 — сразу в очередь на рендер
[povodok-templates] ✓ snapshot [suspense] 30.2 с
[povodok-templates] … ждёт подтверждения «frames»

■ итог за 2 мин 23 с: готово 0, ждут подтверждения 2, ошибки 0
    проект                   итог                     всего      ml  рендер очередь  результат
  … povodok                  ждёт «script»             0:00    0:00       —    0:00  —
  … povodok-templates        ждёт «frames»             2:23       —    2:23    0:00  —
```

Код выхода `run`: `0` — всё готово, `3` — кто-то ждёт подтверждения, `1` — есть ошибки, `2` — ошибка запуска
(нет проектов, нет Python).

### watch

* новая папка с `reel.yaml` или изменённый `reel.yaml` → проект ставится в конвейер;
* проект ждал подтверждения, а его `.reels-state.json` изменился (сделали `python -m reels approve`) → продолжает;
* каждая новая строка в `<inbox>/topics.txt` (пустые и `#…` пропускаются) →
  `python -m reels draft "<тема>" -o <inbox>/<slug>`; обработанные темы записываются в
  `<inbox>/.reels-app-topics.done` (удалите строку оттуда, чтобы повторить);
* `Ctrl+C` — новые фазы не начинаются, текущие процессы дорабатывают (не дольше `--grace`), второй `Ctrl+C`
  убивает их сразу (вместе с дочерними ffmpeg/node).

### tui

Слева — проекты со значком (`✓` готово, `▶ ml`/`▶ render` — идёт, `⋯` очередь, `… take` — ждёт точку,
`✗` — ошибка), справа — сетка этапов выбранного проекта, точки, готовые ролики и журнал вывода.
Клавиши: `↑↓`/`jk` — выбор, `r` — запустить выбранный, `R` — все, `a` — подтвердить ждущую точку
(`python -m reels approve`, затем проект снова в очереди), `o` — открыть mp4 или лист кадров
(`xdg-open`/`open`/`start`), `q` — выход (если идут процессы — второй `q` прерывает их).
Состояние обновляется через `status --json` каждые 2 с.

## Как планируется конвейер

Каждый проект проходит две фазы, каждая — один процесс `python -m reels run <dir> --no-input`:

* **ml** = `run --until music` (check → accent → voice → align → music): TTS и MusicGen занимают видеокарту
  целиком, поэтому фазе нужен **слот GPU** (`--gpu-slots`, по умолчанию 1);
* **render** = `run` до конца (build → snapshot → render → finish): рендер HyperFrames сам грузит несколько ядер,
  поэтому нужен **слот CPU** (`--cpu-slots`, по умолчанию max(1, ядра/4)).

```
слот GPU  │ A:ml ──────┐ B:ml ──────┐ C:ml ─────┐
          │            ▼            ▼           ▼
слот CPU1 │            A:render ───────────┐  C:render ──────
слот CPU2 │                         B:render ──────────┐
          └──────────────────────────────────────────────────► время
```

* у проекта не больше одного процесса Python за раз (он держит один слот и пишет свой `.reels-state.json`),
  но фаза ml проекта B идёт параллельно с рендером проекта A;
* перед запуском `run` спрашивает `status --json`: у кого озвучка и музыка уже готовы и подтверждены, тот
  сразу встаёт в очередь на рендер, не дожидаясь видеокарты (`--no-precheck` отключает);
* код `3` (контрольная точка) — проект паркуется как «ждёт «gate»», слот освобождается, конвейер идёт дальше;
* код `1` (этап упал) — повтор фазы до `--retries` раз; код `2` (ошибка `reel.yaml`) — без повторов;
  в итог попадает строка `✗ …` из stderr;
* `--yes` передаётся в Python как есть (автопилот подтверждает точки).

События планировщика (`ProjectStarted`, `Phase`, `Line`, `Waiting`, `Done`, `Failed`) идут по каналу
`tokio::mpsc` — их читают и прогресс `run`, и `watch`, и `tui`.

## Связь с Python-пакетом

`reels-app` не дублирует логику конвейера: кэш, хэши, точки и отчёты — в `reels/pipeline.py`.
Используемый контракт:

* `python -m reels status --json <dir>…` — состояние проектов (поля `dir`, `slug`, `title`, `edits`, `stages`,
  `gates`, `outputs`, `report`, `error`);
* `python -m reels run <dir> --no-input [--yes] [--until STAGE] [--edit E]…` — коды `0/1/2/3`, строки
  прогресса `▸ / ✓ / ·` в stdout, ошибки `✗ …` в stderr;
* `python -m reels approve <dir> <gate>`, `python -m reels draft "<тема>" -o <dir>`.

## Разработка

```bash
cd app
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
```

Тесты планировщика (Unix) подменяют Python сценарием на `sh` (через `Python { exe, .. }`), который спит,
печатает строки прогресса и выходит с кодом 0/1/2/3 — проверяются лимиты слотов, перекрытие ml/render,
ожидание, ошибки, повторы, `--yes` и остановка по Ctrl+C.
