# Reels Desktop — настольное приложение для local-ai-reels

Окно на Tauri 2 (Rust + системный WebView) поверх Python-конвейера `python -m reels`. Приложение не
заменяет конвейер: оно запускает те же команды (`status --json`, `run`, `approve`, `new`, `draft`),
показывает их вывод вживую и даёт работать с контрольными точками мышкой.

Два режима — переключатель «Просто / Эксперт» в шапке, выбор запоминается.

## «Просто» — для всех

![Режим «Просто»: тема, оформление и шаги работы](screenshot-simple.png)

1. Напишите, **о чём ролик** (сценарий напишет локальная LLM — `reels draft`), или вставьте **свой текст**:
   4 коротких абзаца через пустую строку (крючок, факт, поворот, вывод; до 60 слов).
2. Выберите оформление: «Чертёж», «Ночь», «Бумага», «Моно».
3. «Сделать ролик» — дальше конвейер идёт на автопилоте (`run --yes`), а на экране — понятные шаги:
   «Пишем сценарий» → «Озвучиваем» → «Собираем кадры» → «Рендерим» → «Готово».

![Готовый ролик: плеер, «Сохранить видео», «Открыть папку»](screenshot-simple-done.png)

В конце — плеер с готовым видео (если монтажей несколько — переключатель), «Сохранить видео» (копия mp4 куда
угодно) и «Открыть папку». Ошибки объясняются простыми словами: «Не найден Python с пакетом reels —
установите: pip install local-ai-reels», «Нет видеокарты — используйте голос Piper или готовую озвучку» и т. п.
Подробный журнал — по ссылке «Подробности». Можно запустить несколько роликов подряд: они встанут в очередь.

Ролики складываются в папку `~/Видео/Reels` (или `~/Reels`); поменять — ссылка «Папка роликов».

## «Эксперт» — всё управление конвейером

![Режим «Эксперт»: проекты, этапы, выбор дубля, журнал](screenshot.png)

- **Рабочая папка** с проектами (`reel.yaml` в подпапках первого и второго уровня) — запоминается.
  Список проектов со статусами: «готово», «ждёт: дубль», «в работе: сборка», «в очереди», «ошибка».
- **Новый ролик** (`reels new`, из шаблона или примера из `examples/`) и **Черновик по теме** (`reels draft`).
- **Полоса этапов** check → accent → voice → align → music → build → snapshot → render → finish с ромбами
  контрольных точек (зелёный — подтверждена, жёлтый — ждёт).
- **Панель контрольной точки**, когда конвейер ждёт человека:
  - `script` — блоки сценария с числом слов и лимитом;
  - `accents` — текст с ударениями (гласная после «+» выделена);
  - `take` — таблица дублей: голос, seed, сверка Whisper, длительность, что услышано, плеер и кнопка
    «Выбрать» (дубль копируется в `build/voice/master.wav`, `choice.json` обновляется, `"manual": true`);
  - `frames` — контактный лист каждого монтажа и замечания автопроверки вёрстки из `qa.json`.
  - «Подтвердить и продолжить» = `reels approve` + новый запуск; «Только подтвердить».
- **Запустить** (`run --no-input`), **Автопилот** (`--yes`), **Остановить** (останавливается всё дерево
  процессов: Python, ffmpeg, node, браузер), **Показать в папке**.
- **Результаты**: плеер для каждого монтажа (`out/<slug>-<монтаж>.mp4`), «Показать в папке», `report.md`.
- **Журнал**: stdout/stderr Python в реальном времени, фильтр по проекту.
- **Очередь**: на проект — не больше одного запуска; сколько проектов идёт одновременно — настройка
  «одновременно» в шапке (по умолчанию 1: рендер и модели и так занимают видеокарту целиком).

## Какой Python используется

1. переменная окружения `REELS_PYTHON` (путь или имя команды);
2. иначе `python3`, затем `python` из `PATH`.

Если пакет `reels/` лежит в папке-предке проекта, рабочей папки или самой программы (например, вы собрали
приложение внутри клона репозитория), этот корень добавляется в `PYTHONPATH` — `pip install` не нужен.
Иначе нужен установленный пакет: `pip install -e .` в корне репозитория.

## Сборка

Нужны Rust (stable) и системные библиотеки WebView.

Linux (Ubuntu 22.04+ / Debian 12+):

```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libayatana-appindicator3-dev \
  libsoup-3.0-dev libjavascriptcoregtk-4.1-dev build-essential pkg-config
```

macOS — Xcode Command Line Tools; Windows — WebView2 (есть в Windows 10/11) и MSVC Build Tools.

```bash
cd app/desktop
cargo build --release            # программа: target/release/reels-desktop
./target/release/reels-desktop

npx @tauri-apps/cli@2 build      # установщики: target/release/bundle/ (deb, AppImage, dmg, msi)
```

Это отдельный Cargo-пакет со своим `[workspace]` и своей папкой `target/` — он не входит в рабочее
пространство `app/` (reels-core, reels-app). Интерфейс — обычные HTML/CSS/JS в `dist/` без сборщика и npm-зависимостей.

Проверки:

```bash
cargo test                       # мост к Python и очередь — на поддельном интерпретаторе tests/fake_python.sh
cargo clippy --all-targets -- -D warnings
```

Превью интерфейса без Rust: откройте `dist/index.html` в браузере — подключится фикстура `dist/fixture.js`
(`#simple`, `#simple-done`, `#expert`, `#expert-done` в адресе — разные экраны). Так сделаны скриншоты выше.

CI: `.github/workflows/desktop.yml` — fmt, clippy и тесты на Linux, установщики для Linux, macOS и Windows
в артефактах сборки.

## Устройство

| Файл | Что |
|---|---|
| `src/python.rs` | поиск Python и корня пакета, `python -m reels …`, разбор `status --json`, коды выхода (0 готово, 3 ждёт подтверждения, 1 ошибка этапа, 2 ошибка reel.yaml), строки прогресса `▸ ✓ ·` |
| `src/runner.rs` | очередь: один запуск на проект, общий предел, живой вывод (события `run-log`, `run-finished`, `runs-changed`), остановка дерева процессов, цепочки команд (`draft` → `run`) |
| `src/project.rs` | файлы контрольных точек (`accents.json`, `takes.json`, `choice.json`, `qa.json`, `report.md`), выбор дубля, блоки «своего текста» в `reel.yaml` |
| `src/error.rs` | ошибки по-русски и подсказки простым языком |
| `src/lib.rs` | команды Tauri, настройки (папка конфигурации приложения, `settings.json`), доступ к файлам проекта через asset-протокол |
| `dist/` | интерфейс |
